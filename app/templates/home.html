OWASP TOP 10 PROACTIVE CONTROLS MAPPING

ARCHITECTURE TRACEABILITY, ACTIVE CODE LOCATIONS, AND THREAT ELIMINATION PROOFS
[ OFFICIAL OWASP TOP 10 ↗ ]
C1

Implement Access Control

FUNCTION IN CODE: app/__init__.py::_enforce_login() • app/security/decorators.py::@owner_required • app/security/decorators.py::@role_required
Enforces a deny-by-default perimeter across all non-auth routes, strict note ownership boundaries, and parity 404 responses for unauthorized note requests. Also locks the last remaining administrator from demotion.
> WHAT HAPPENS IF NOT PRESENT:
Insecure Direct Object References (IDOR) & Broken Access Control: Any authenticated user could change the note ID in the URL (e.g. /notes/2) to read, edit, or purge any other user's private notes. Attackers could also enumerate company note IDs or escalate privileges to administrator without authorization.
C2

Use Cryptography to Protect Data

FUNCTION IN CODE: app/security/passwords.py::hash_password() • app/security/passwords.py::verify_and_rehash() • app/config.py::BaseConfig.SECRET_KEY
Encrypts all passwords using Argon2id (winner of the Password Hashing Competition) with automatic parameter re-hashing. Enforces that SECRET_KEY must be provided via environment variables (never hardcoded), refusing to start if missing.
> WHAT HAPPENS IF NOT PRESENT:
Catastrophic Credential Exfiltration: If the database file is accessed or leaked, weak hashing (like MD5, SHA-1, or unsalted SHA-256) allows attackers to crack millions of passwords per second using GPU rainbow tables. Hardcoded secret keys allow attackers to forge session cookies and impersonate anyone.
C3

Validate all Input & Handle Exceptions

FUNCTION IN CODE: app/blueprints/auth.py::RegisterForm • app/models.py::SQLAlchemy ORM • app/errors.py::register_error_handlers()
Validates all form inputs using WTForms (regex for usernames, length minimums), executes database access purely through SQLAlchemy ORM parameterized queries (zero string-concatenated SQL), enables autoescaping, and serves generic error pages without stack traces.
> WHAT HAPPENS IF NOT PRESENT:
SQL Injection (SQLi) & Diagnostic Leakage: Attackers submit inputs like ' OR 1=1 -- to bypass logins or inject DROP TABLE notes;. Unhandled exceptions display raw Python tracebacks, revealing database schema, internal filesystem paths, and library versions to attackers.
C4

Address Security from the Start

FUNCTION IN CODE: docs/threat-model.md (STRIDE) • docs/controls-map.md (Traceability Matrix)
Embeds formal security design prior to implementation using a full STRIDE Threat Model (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) and a line-level controls verification matrix.
> WHAT HAPPENS IF NOT PRESENT:
Architectural Flaws & Security Blind Spots: Security retrofitted at the end of development inevitably leaves foundational structural gaps (like un-pinnable SSRF endpoints or missing CSRF tokens on state-changing actions), requiring expensive and error-prone architectural rewrites.
C5

Secure By Default Configurations

FUNCTION IN CODE: app/config.py::BaseConfig.DEBUG = False • app/cli.py::create-admin CLI command
Enforces DEBUG = False across all configurations. Prevents default credentials by having no initial admin; administrators must be provisioned interactively through a dedicated CLI command with a mandatory password prompt (min 8 chars).
> WHAT HAPPENS IF NOT PRESENT:
Immediate System Compromise via Default Accounts: Automated internet scanners scan for standard accounts (admin:admin or admin:password). If debug mode is inadvertently left active in production, interactive web debuggers (like Werkzeug) allow attackers to execute arbitrary shell commands directly in the server environment.
C6

Keep your Components Secure

FUNCTION IN CODE: requirements.txt • pip-audit dependency scanner
Maintains strictly pinned dependency versions in requirements.txt and provides integrated pip-audit instructions to continuously inspect packages against the PyPA Advisory Database and known CVEs.
> WHAT HAPPENS IF NOT PRESENT:
Software Supply Chain Attacks: Using floating or unpinned dependencies leaves the system vulnerable to known vulnerabilities in outdated dependencies (e.g., HTTP request smuggling in old urllib3 or remote code execution in outdated template engines) without the developer ever knowing.
C7

Secure Digital Identities

FUNCTION IN CODE: app/blueprints/auth.py::@limiter.limit() • app/blueprints/auth.py::session.clear() • app/config.py::PERMANENT_SESSION_LIFETIME
Applies a rate limit of 5 attempts per minute on login and registration POST requests, regenerates sessions on login (session.clear()), enforces a 30-minute idle session timeout, and uses generic error messages to eliminate username enumeration.
> WHAT HAPPENS IF NOT PRESENT:
Credential Stuffing & Session Fixation: Botnets fire thousands of breached password lists per minute until an account is breached. Without session regeneration, an attacker who plants a session cookie on a shared terminal automatically takes over the victim's authenticated session once they log in.
C8

Leverage Browser Security Features

FUNCTION IN CODE: app/__init__.py::Talisman Content-Security-Policy • app/extensions.py::CSRFProtect • app/static/style.css (100% external)
Configures a strict CSP (no unsafe-inline anywhere), X-Frame-Options: DENY, X-Content-Type-Options: nosniff, HttpOnly and SameSite=Lax cookie flags, HSTS in production, and CSRF token protection on every state-changing POST action.
> WHAT HAPPENS IF NOT PRESENT:
Cross-Site Scripting (XSS) & Clickjacking: If a user stores a malicious payload, without a strict CSP, inline scripts execute in other users' browsers to steal cookies and forge actions. Without clickjacking protection, the site can be framed invisibly to trick users into triggering deletions.
C9

Implement Security Logging and Monitoring

FUNCTION IN CODE: app/security/logging_setup.py::setup_logging() • app/security/logging_setup.py::log_security_event() • app/blueprints/admin.py::view_log()
Records structured events for LOGIN_SUCCESS, LOGIN_FAILED, ACCESS_DENIED, ROLE_CHANGED, and SSRF_BLOCKED into a 1 MB rotating file handler (5 backups). Features an admin terminal viewer.
> WHAT HAPPENS IF NOT PRESENT:
Undetected Infiltration & Zero Forensic Visibility: Intrusions, brute-force attempts, and insider privilege abuse go completely unnoticed. When a data breach occurs, security analysts have zero historical evidence to identify the root cause, compromised accounts, or timeline.
C10

Stop Server Side Request Forgery (SSRF)

FUNCTION IN CODE: app/security/ssrf.py::safe_fetch_url() • app/security/ssrf.py::_resolve_and_validate() • app/security/ssrf.py::_forced_ip_resolution()
Restricts preview fetches to HTTP/HTTPS, resolves DNS and inspects every IP to reject loopback, link-local, and RFC 1918 private subnets. Pins socket connection to vetted IP (anti-DNS rebinding), forbids redirects, streams at most 1 MB, and parses only title/description metadata.
> WHAT HAPPENS IF NOT PRESENT:
Cloud Infrastructure Compromise & Internal Network Pivoting: An attacker inputs http://169.254.169.254/latest/meta-data/ to steal AWS/GCP/Azure IAM credentials, seizing the entire cloud project. Attackers can also probe internal microservices, Redis databases (http://127.0.0.1:6379), or trigger remote code execution.
